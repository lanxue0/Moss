# v1-spec 评审意见

> 评审对象：`docs/v1-spec.md`（941 行，commit `9a3472f`）
> 评审时间：2026-10-23
> 评审标准：**这份文档能不能直接照着开工**，而不是"写得全不全"。
> 说明：本文只记录问题与改法，不改动 `v1-spec.md`。改不改、怎么改，另议。

## 0. 结论

**架构和规划是认真做过的，可以直接开工；但有 4 个洞会直接卡住实现，不是文档瑕疵，是逻辑没闭合。**

| 维度 | 判断 | 说明 |
|------|------|------|
| 产品设计 | 机制 8 / 10，闭环 5 / 10 | 三级显示、置信度门槛、五道闸门、每期中止条件是真本事；但有 4 处"被引用了却没定义" |
| 技术选型 | 8 / 10 | Electron + Python 双运行时选对了，理由站得住；4 处细节要改，不影响架构 |
| 项目规划 | 7 / 10 | 有分期、有验收、有中止条件，高于一般个人项目；缺环境前置与测试边界 |
| 项目结构 | 8 / 10 | 目录到文件级、四条依赖禁令、命名规范、数据分家，是真规范 |

**最关键的一句：这 4 个洞不补，P2 第一天就会撞墙。**

修复量很小（集中在 7.4 / 8.2 / 9.1 / 9.2 / 2.1 / 4.1 / 8.4 / 11.1 + 新增一节环境说明），但**必须在写 `detectors.py` 之前补**，否则写完 D5 会发现一半触发条件永远为假。

## 1. 产品设计评审

### 1.1 先说做对了什么（不要动）

这四样是这份文档真正的价值，后续修改时**不要手痒去"优化"它们**：

1. **三级显示（Tier 0/1/2），且 Tier 2 只能由用户触发**——系统永不主动展开气泡。这是防止产品变成弹窗广告的最后一闸。
2. **置信度 < 0.7 一律不归因，判"未归类"**——宁可少知道，也不要让用户怀疑。这条挡住了"猜错一次，十次做对也补不回来"的信任崩塌。
3. **五道闸门 + 检测器与措辞分离**——LLM 只做"事实→人话"翻译，不参与判断。这决定了它不会因为模型抽风突然开始唠叨。
4. **每期都写了中止条件**——尤其"一周后你打开「今天」页 < 2 次，说明回顾对你没价值"（§12），是全文档最狠也最对的一句。没中止条件的路线图等于承诺。

### 1.2 四个必须补的洞

#### 洞 1 · 里程碑根本无法自动判定（阻断级）

**位置**：§8.2 `milestones`、§8.3 末尾、§9.1 D5、§9.4 模板 `"D5": "{goal}：{milestone} 完成，比计划早 {days} 天。"`

**问题**：`milestones` 只有 `{id, title, target(日期)}`，`success` 是中文字符串（"i18n 分支合并进 main 并通过验收"），**机器无法判定完成**。于是：

- D5 的触发条件"里程碑达成"永远为假 → 一半逻辑是死的
- 模板里的 `{milestone}` / `{days}` 永远填不出数

这不是文档写得不够细，是**设计上试图让机器判断一件它没有信息的事**。

**改法**：v1 里程碑纯手动，`milestones: [{id, title, target, done: false}]`，面板目标页一个勾选框。
D5 只保留 `longest_block` 破 14 日记录这一条触发条件。

**理由**：完成没完成本来就该你自己判断。机器假装知道，只会制造"它说完成了其实没完成"的不信任。

#### 洞 2 · "日报"被引用 4 次，全文档没有定义（阻断级）

**位置**：§5.2 规则 2（339 行）、§9.2 G4（633 行）、§9.2 G5（634 行）、§10.3 隐形档（741 行）

**问题**：配额用完、余额不足、发光超限，三处都写"只进日报"。但**日报是什么、什么时候生成、在哪儿看，一个字没有**。
它其实是所有抑制逻辑的唯一出口——出口不存在，等于所有抑制都变成了静默丢弃。

**改法**：**删掉"日报"这个词，v1 不生成日报。** 被抑制的消息进面板「它说了什么」页的 `suppressed` 列表，字段带 `suppress_reason`（G1–G5）。

**理由**：`scripts/digest.py` 已经在做"今天干了什么"的每日总结。再造一个"日报"就是第三个真相源。v1 的消息抑制只需要一个可查列表，不需要一份文档。

#### 洞 3 · 信任余额只有扣分，没有恢复规则（阻断级）

**位置**：§9.2 G5（634 行）

**问题**：`余额 = Σ(有用 +1 / 烦人 −3)`，余额 < 0 则静默 7 天。**7 天之后呢？重置为 0，还是继续 −1？**
没定义就是一种死锁：一次误判 → 静默 7 天 → 余额仍是 −1 → 继续静默。用户会以为它坏了。

**改法**：明确"**静默满 7 天后余额重置为 0**"，且每次静默开始/结束在面板留一条记录（时间、原因、是哪条消息导致的）。

**理由**：可预期 > 聪明。用户能理解"罚 7 天然后重来"，理解不了"为什么它一直不说话"。

#### 洞 4 · 双真相源没定权威（阻断级）

**位置**：§14、§4.4

**问题**：`digest.py` 写 `scripts/out/digest/`，brain 写 `~/.moss/moss.db`。"今天干了什么"会有**两个答案**，且两边算法不同（digest 按提交 sha 去重、brain 按会话算分钟）。迟早对不上，对不上时你不知道信哪个。

**改法**：明确 **`~/.moss` 是 v1 唯一权威**。`scripts/out/digest/` 降级为历史产物，`digest.py` 标记为 legacy（保留可跑，不再作为日常入口）。

**理由**：一个自用工具，出现两个互相矛盾的数，比没有数更糟——你会开始怀疑整个系统。

## 2. 技术栈评审

### 2.1 选对的（不要动）

- **Electron + Python 双运行时**：Python 侧用 ctypes 拿前台窗口、digest 的 git 采集逻辑都已踩过坑，重写等于重踩。Node 侧要么 `ffi-napi`（随 Electron 版本炸），要么写 native 模块（没必要）。这个判断是对的。
- **换壳条件写死**（常驻 > 250MB 或空闲 CPU > 2% 持续一周）：把一个模糊的技术债变成了可触发的决策，很好。
- **壳体只做三件事**（建窗口、守护 brain、切鼠标穿透）：所以换 Tauri 只换一个包。这个隔离是真的。

### 2.2 四处要改

#### 5 · `Electron 30+` 是 2024 年的版本（§2.1，49 行）

2026 年 10 月早就是 v4x 了。**写死主版本号必然过时**，而且会误导安装。
**改法**：改成"当前最新稳定版"，在 §4 环境说明里写"实际版本以 `pnpm install` 为准"。

#### 6 · 单 HTML 用 `?win=` 区分三个窗口（§4.1，158 行）

electron-vite 的标准做法是**多 HTML entry**。用一个 `index.html` + query 参数会丢掉按窗口分包——三个窗口全量加载同一份 bundle，面板的代码（5 个页面 + 依赖）会被塞进那个 160×160 的球窗口。

**改法**：`ball.html` / `bubble.html` / `panel.html` 三个 entry，`windows.ts` 里各自 `loadFile` 对应文件。

#### 7 · 首跑"2 分钟"不成立（§8.4）

3 个目标 ×（标题 + 期限 + 勾仓库 + 输入 2 个关键词）+ API 三项 + 点"测一下"，2 分钟做不到。API key 还要去别处取，本身就是分钟级操作。

**改法**：
- 第一天只要求 **1 个目标 + 2 个关键词**（`signals` 是准确率命门，这条不能省，但数量可以降）
- **API 推迟到它第一次真要说话时再引导**——有模板兜底，不填也能跑
- 保留"不许超过 2 分钟"，但砍掉的是目标数量和 API 步骤

#### 8 · token 是自我矛盾的过度设计（§11.1，768 行）

文档说 token 写在 `runtime.json`（0600），所有请求带 `X-Moss-Token`。问题是：

- 渲染进程要请求，就得先拿到 token → 路径没定义
- 任何**同用户**的本机进程都能读 `runtime.json`（0600 只挡其他用户）
- 所以它防不住文档里说的"另一个脚本顺手读一下"

**改法**：**删掉 token**，只校验 `Host` / `Origin`。文档里诚实写一句：**"我们不假装防本机进程——同用户的进程本来就挡不住，加 token 只会让人以为它安全。"**

这条和我们自己定的原则是同一句话：宁可少知道，也不要让用户怀疑。

### 2.3 比上面 4 条更实际的问题：P0 的 2–3 天不现实

**问题**：P0 要求三窗口骨架 + 六状态 + 发光 + 穿透 + 开机自启 + 假状态源。但光脚手架就要一天（Node / pnpm / Electron / Vite / TS / electron-vite 三入口）。

**改法**：拆成两段。

| 段 | 内容 | 工作量 |
|----|------|--------|
| **P0a** | 单个最小 Electron 窗口，纯 HTML + CSS，只验证三件事：透明、鼠标穿透、呼吸动画不烧 CPU | 半天 |
| **P0b** | 再上 React、其余两个窗口、六状态、自启 | 1 天 |

**理由**：P0 的验收标准是"你愿不愿意让它待在屏幕上"（§12），这个结论**半天就能拿到**，不需要先把工程化做完。先用最丑的方式把球放上去看一天，比搭完脚手架再看更有价值。

## 3. 规划与规范评审

### 3.1 规划：有，质量高于一般个人项目

P0–P3 分期、每期验收标准、每期中止条件——这套东西很多人做了十年项目都没写过。尤其"顺序不能反"那段（P0 验证你愿不愿意让它待着 → P1 验证你会不会看 → P2 验证它说话你烦不烦）是真判断。

### 3.2 缺三样

#### 9 · 环境前置没写（补一节）

文档里只有 `pnpm dev` 这一句。clone 下来第一句命令就会失败。要写清：

| 项 | 要求 |
|----|------|
| Node | ≥ 22（本机已有 22.22 / 24.13） |
| 包管理 | pnpm 9 |
| Python | 3.13（本机 managed 路径已固定） |
| 系统 | Windows 10 1809+（透明窗口 + `setIgnoreCursor` 所需） |
| 浏览器 | Chrome 或 Edge，带 `--remote-debugging-port=9222`（URL 采集可选） |

#### 10 · 测试策略只有一行 `pnpm test`（补一节）

个人项目不该追求覆盖率，但**必须有测试的只有三个地方**，因为它们出错时你发现不了：

| 模块 | 测什么 | 为什么必须 |
|------|--------|-----------|
| `attribute/` | 表驱动，喂真实窗口标题样本，断言 goal_id + confidence | 归因错了，后面所有数字都错，且**看起来完全正常** |
| `detect/budget.py` | 假时钟测冷却、配额、免打扰边界 | 时间逻辑的 off-by-one 不会报错，只会多说话或少说话 |
| `compose/validate.py` | 禁词、长度、必含数字、问号数 | 这是文案纪律的唯一执行点，破了就变成"AI 味" |

其余（UI、SQL 聚合、git 采集）不写单测——git 采集用 `digest.py` 的历史结果做对照，比单测有效。

#### 11 · 无版本 / 分支策略（补一句）

main 直推可以，**不引入 PR 流程**（个人项目，那是负担）。但每个阶段结束打 tag：`p0-ball`、`p1-observe`、`p2-speak`。出问题时能立刻知道"上次能跑是哪一版"。

### 3.3 结构：全文档最扎实的部分

目录树到文件级、四条依赖禁令、命名规范、数据分家（`~/.moss` vs 仓库）——这些是真规范，能挡住三个月后的自己乱来。

一处小冲突：`services/brain/pyproject.toml` 与项目"零第三方依赖"的硬约定打架。
**改法**：`pyproject.toml` 的 `dependencies` 留空，注明"只用于 pytest 与打包，运行时零依赖"。

## 5. 待定的设计取舍（不是问题，是要你选）

这四条 `v1-spec.md` §15 已经列过，评审时确认它们确实需要你定，且**不影响上面 12 条的修复**：

1. 球默认位置：右下（倾向）还是左上
2. `alongside` 是否带"陪你一起"的暗示（球体向目标色微偏）

4. D1 漂移（刷手机 45 分钟）算不算值得说——最容易被当成监控的一条

## 6. 一句话总结

**这份文档的机制设计是可信的，问题都出在"引用了一个不存在的东西"——里程碑、日报、余额恢复、唯一权威。**
把 4 个出口补上，它就从"一份很好的设计稿"变成"一份可以直接派活的规范"。
