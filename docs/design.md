## 0. 先说三个判断

在你原来的描述里，"统计我在做什么"是明线，"根据目标提醒我"是需求。但我认为这个产品真正的价值点在这三件事上，而且顺序很重要：

**① 最值钱的不是桌宠，是"连续的低带宽反馈通道"**

通知是二元的、昂贵的：要么响（打断你），要么不响（什么也没发生）。中间没有灰度。

而一个常驻在你屏幕角落的小人，是一个**连续、廉价、可忽略**的通道。它可以歪一下头，可以在你连续工作 90 分钟时伸个懒腰，可以在你打开第 6 个标签页找同一个报错时坐直身子看你一眼——这些都在传递"我注意到了"，且**一句话都没说，你可以完全不理它**。

这才是桌宠形态的产品理由。不是为了可爱。传统 productivity app 做不到这件事，因为它们没有一个可以承载连续状态的实体。

**② 最值钱的不是采集能力，是"关于你的长期语义记忆"**

桌面端采集窗口标题、URL、文件路径，技术上不难，谁都能做。护城河不在采集，在**半年后它知道你三月卡在哪个概念、你写代码最顺的是下午两点到五点、你每次说"今天要把这篇论文看完"实际都在第 4 页停下来**。

这种记忆换掉就等于丢失自己的历史。这才是迁移成本。

**③ 最值钱的不是提醒，是"闭嘴的克制"**

同类产品 90% 死在"太烦"。一个会主动闭嘴的助手是稀缺品。所以"什么时候不说"要和"说什么"一样被当成一等公民来设计（第 4.6 节）。

## 1. 自用版：能力边界消失了，但换来三个新问题

> v0.2 修订：本项目是**单人自用**，自己授权、自己承担，所以不需要为"商店审核 / 合规 / 说服用户"做任何妥协。采集可以直接打满——前台窗口、进程名、浏览器 URL 与页面正文、界面无障碍树、截图 + 本地 OCR、剪贴板、手机 adb。
>
> 这意味着**判断方式从"猜"变成"读"**。归类的准确率基础从 60% 抬到 90%+，这是整个产品可信度的地基。商业版永远拿不到这个，你拿得到。

但消掉一个约束，换来三个更硬的问题：

| 新问题 | 为什么它比"权限"更难 |
|---|---|
| **烦人** | 自用也会把一个小人关掉。没有用户调研兜底，只有你自己的忍耐度 |
| **维护成本** | 单人项目通常死于"三周后跑不起来了"，不是死于想法不好。技术选型必须能半年后一键启动 |
| **结论可信** | 数据越多，越容易得出"看起来对、其实错"的判断。自用版的门槛不是"不许错"，是"错了你 3 秒内能看出来" |

**所以自用版的设计重心，从"怎么拿到数据"整体挪到"怎么让每个判断可解释、可一键推翻"。** 这也是为什么数据模型里每一条结论都必须能指回原始记录。

具体怎么搭见 `../scripts/` 目录和《自用版实施方案》。

## 2. 四层结构

用户在屏幕上只看见最上面那一层。下面三层是它安静工作时的地方，也是全部工程量和护城河所在。

**① 感知层（全本地）** —— 窗口标题、URL、文件路径、git 仓库、输入节奏、空闲状态。这一层不该有任何网络请求。

**② 理解层** —— 把碎片切成"会话"（30 秒无操作即切段），再把每个会话归类到某张目标卡，并给出置信度。**铁律：置信度低的进"未归类"，绝不硬猜。** 猜错一次造成的信任损失，十次正确也补不回来。

**③ 记忆层** —— 情节记忆（今天/本周发生了什么，可回放）、语义记忆（你的项目、人、偏好、知识状态）、工作记忆（当前会话）。

**④ 表达层** —— 小人的姿态、一句话、晚间日报。这一层的信息密度必须**远低于**下面三层，这是设计纪律：内部可以很复杂，对外必须极其克制。

## 3. 核心机制

### 3.1 目标卡：把"目标"变成可计算的东西

用户写下的不是一个待办，而是一张卡：

| 字段 | 说明 | 为什么要这个字段 |
|---|---|---|
| 目标陈述 | "三月底前把 RAG 那套东西搞明白并做出 demo" | 名词，可拆 |
| **为什么** | "因为想换到算法岗" | **最关键**。所有提醒的话术都从这句话里长出来。没有 why 的提醒就是催促 |
| 期望投入 | 8 小时/周 | 进度的分母 |
| 里程碑 | 3 个，带日期 | 进度的分子 |
| 可接受活动 | 看论文、写代码、看视频课 | 用于归类 |
| 明确排除 | 刷 B 站、看球 | 用于"温和地指出" |

**设计要点：目标卡必须由用户亲手写，不能由 AI 代笔。** 亲手写的目标才有承诺感，AI 生成的目标只是订阅了一份催促服务。

### 3.2 活动 → 目标的映射

不做秒级判断，做**会话级**判断，一天大概 80–150 个会话，成本可控，错误也更容易被用户理解。

流程：
1. 切分：30 秒无输入/焦点变化 → 切段
2. 特征：应用类别 + 标题关键词 + URL 域名路径 + 文件后缀 + git 仓库名 + 时间分布
3. 归类：规则库（用户纠正过的）优先 → embedding 最近邻 → LLM 兜底
4. 输出：`(目标卡, 置信度)`
5. 置信度 < 0.6 → 进"未归类"。日报里问一句："下午 3 点到 4 点你在 Notion 里，这算哪个目标？"

**每一次判断都要能展开看到依据，并且一键纠正。** 纠正不是修数据，是训练它——这是用户和它建立关系的仪式。

### 3.3 进度怎么写

**永远不要输出"你落后了"。** 那是裁判的语气。

给它三条曲线：承诺投入（计划）、实际投入（事实）、里程碑完成度（成果）。三条只在明显分叉时才提。

话术模板：

> 按现在这个节奏，这个目标大概会在 4 月 12 日完成。你原本想 3 月底。中间差 12 天。
> 要不要 ① 每周多两个晚上 ② 砍掉 demo 里的第二个场景 ③ 把期限改到 4 月中？

**判断变成选项，助手就不是裁判，是合伙人。**

明确不做的：效率评分、排行榜、连续打卡天数、红色警告图标。这些都是在制造焦虑换取日活，代价是口碑。

### 3.4 学习巩固引擎

这是"它真的像助手"和"它只是个计时器"的分界线。

- **知识原子抽取**：从你实际读的文档/视频/代码/论文里抽出概念，记下出处、首次暴露时间、停留时长、是否回看
- **暴露即复习**：不要求你建卡片。它在自然间隙（任务切换、空闲 >90 秒、关掉一个窗口）问**一个**问题，一个问题就够，可以不回答
- **调度**：用 FSRS，但输入信号是"你的实际再暴露"，而不只是"卡片复习记录"——你今晚又用到了这个概念，它的复习间隔就该重算
- **主动重构**：把你这周读的三篇东西，串成一段"这三篇其实在讲同一件事"的话。这是它唯一能做的、比你自己更强的事

差异化一句话：**别家让你背别人做的卡片，它从你已经读过的东西里出题。**

### 3.5 卡住检测

我认为这是整个产品里最有情感价值的功能。

信号（都是低成本的）：
- 同一段文字反复上下滚动
- 同一个报错，在浏览器里来回搜了三轮
- 同一个视频反复拖回同一段
- 光标在同一行停了 3 分钟以上
- 一个文档只读了前两页就关了，隔天又打开前两页

响应是**分级**的，这点很重要：

1. **先不说话**——小人歪一下头，或者把手里的东西放下
2. 你点它 / 鼠标停上去，它才开口："这一段你回来三次了。要不要换个讲法？"
3. 你同意，它给一个不同角度的解释，或者画一张图

从"监督你"变成"替你解围"。用户对这个产品的感情，就是在这一个个瞬间里建立的。

### 3.6 打断经济学

这是全系统最需要认真设计的部分，比追踪算法难十倍。

每一次想说话，都要连过三道闸：

**闸 1 · 值不值得**（价值门槛）
这件事值不值得占用一次注意力？四类才放行：省时、防坑、省钱、情绪价值。其余全部不发。"你今天专注了 3 小时 20 分"不属于这四类，属于自我感动，砍掉。

**闸 2 · 现在合不合适**（时机窗口）
正在连续打字、正在会议中、正在 debug 循环里 → 排队，等下一个自然断点。自然断点 = 切换任务、空闲 >90 秒、保存文件、合上笔记本。

**闸 3 · 余额够不够**（信任余额）
有用 +1，烦人 −3。余额 < 0 → 自动静默 7 天，只出日报。这是给系统的惩罚机制，也是给用户的保险。

另外两道软约束：
- **每日说话配额**：默认 3 次。用完就只能用姿态表达
- **话术纪律**：只描述事实和选项，不做评价；用疑问句，不用祈使句；不说"你应该"，说"要不要"

## 4. 小人本身的设计

### 4.1 状态机

| 状态 | 触发 | 表现 |
|---|---|---|
| sleep | 你离开 >10 分钟 | 趴着/打盹，屏幕亮度降低 |
| idle | 无目标活动 | 慢动作，偶尔看向你 |
| **alongside** | 你正在某个目标卡上工作 | 坐在旁边一起做事，**默认状态，不打扰** |
| curious | 检测到值得说的事 | 放下手里的东西、抬头、歪头——**先做动作，不开口** |
| speaking | 你主动交互 | 展开对话气泡 |
| thinking | 每日整理时 | 翻本子、写字，一天一次 |

关键：**姿态承载信息，文字只承载内容。** 默认状态下屏幕上不该出现任何数字。数字只在点开时出现。

### 4.2 两条反常识的拟人化原则

**① 不要写实人脸。** 恐怖谷是一方面，更重要的是：一张人脸会让人产生"被盯着"的感觉。做抽象小生物，做侧影。

**② 它应该更多是"在旁边"，而不是"看着你"。** 侧坐、背影、自己也在忙自己的事、打盹。这个产品最大的情感风险不是"不准"，是**"被注视感"**。一个总在盯着你的小人，两周就会被关掉。

**③ 存在感滑杆**：隐形 / 安静陪伴 / 主动教练。默认"安静陪伴"。这个滑杆比任何设置项都重要，它把"要不要被打扰"的控制权明确交还给用户，也是面对"太烦"这个头号失败模式的逃生门。

## 5. 一天的使用剧本

> **07:40** 开机。小人已经在角落坐着了，手里拿着一本书的样子。没有问候，没有"早安，今天也要加油哦"。
>
> **09:12** 你在写代码。它换了个姿势，和你一样面朝屏幕，安静待着。
>
> **11:30** 你打开 B 站。它抬头看了一眼，又低下头。**什么也没说。**（这是设计，不是 bug）
>
> **14:05** 你在搜同一个报错第三次。它放下书，歪头看你。你还没理它。
>
> **14:09** 你点了它。
> "这个错你从 13:47 搜到现在了。看起来是版本不匹配，不是你的逻辑问题。要不要我把你项目里那个 lock 文件看一下？"
>
> **17:40** 你保存了文件，刚要切窗口。它开口了（这是今天第 1 次主动说话）：
> "上午那篇 RAG 的笔记你写了一半。现在要不要用两分钟把剩下那半句补完？补完今天就够了。"
>
> **21:20** 你合上电脑前点它。它给了一张今天的卡片：
> —— 今天在"RAG demo"上 3 小时 10 分，比你这周平均多 40 分钟
> —— 有 1 小时 20 分没归到任何目标（B 站 41 分，Notion 整理 39 分）。Notion 那部分算哪个目标？
> —— 那个报错卡了 22 分钟，已经记进"待巩固"，明天早上问你一句
> —— 一句话结论：按这个节奏，4 月 8 日能完成，比目标早 3 天。不用改。
>
> **23:10** 它睡了。

这个剧本里，它一天只主动说了 **2 次**话。

## 6. 冷启动：前 72 小时决定生死

这类产品最大的死亡曲线是"新鲜感两周后无用"。所有设计都要压在"第一次 aha"上。

- **D1：只观察，不出声。** 晚上给一份"今天我看到的你"。不给任何建议。目的是建立"它懂我"。
- **D2：给一条建议，并主动暴露一个它可能弄错的地方**，请用户纠正。这是教会用户"它是可以被纠正的"，比证明它聪明更重要。
- **D3：第一次主动提醒。** 必须挑一个**必然正确**的——比如"你昨天说今天要发的那封邮件，还没发"。

**第一个 aha 必须是"它记得我说过的话"，而不是"它统计得很准"。** 前者是情感，后者是报表。

## 7. 自用版的信任机制（缩水版）

自用不需要说服任何人，但有两个开关必须留，否则你会在一周内把它关掉：

- **物理暂停**：一个 `PAUSE` 文件（或托盘双击），立刻停止记录，小人做"闭眼"动作让你看得见它停了。你会在开会、写日记、看体检报告的时候需要它
- **可删**：一条记录、一段时间、一整个应用，都能删干净。不是为了合规，是为了你敢继续用

其余（加密、审计日志、企业策略、合规）自用可以全部跳过。**要花的力气在"看得见的可解释"，不在"看不见的安全"。**

一个具体做法：日报里每一条结论后面挂 `[证据]`，点开就是那几分钟的原始窗口标题。凡是挂不出证据的话，就不许说。

## 8. MVP 与路线

| 阶段 | 周期 | 内容 | 验证什么 |
|---|---|---|---|
| P0 | 2 周 | 桌面采集 + 每晚日报，**没有小人** | "它懂我"能不能打动人 |
| P1 | 4 周 | 小人 + 目标卡 + 周进度 | 姿态通道有没有用 |
| P2 | 4 周 | 卡住检测 + 间隔召回 | 从"记录"变"帮忙" |
| P3 | — | 手机轻伴侣（打卡 + 小组件 + 日报推送） | — |

P0 特意不做小人，是为了逼自己先验证核心：**如果一份日报不能让人想每天看，加个小人也救不了。**

## 9. 失败模式（按发生概率排序）

1. **归类错了还去提醒 → 用户觉得被冤枉 → 卸载。** 对策：置信度阈值 + 可展开依据 + 一键纠正 + 永不基于低置信判断说话
2. **两周后没用了。** 对策：D3 之前必须交付第一个 aha；功能重心从"记录"尽快移到"解围"
3. **变成焦虑制造机。** 对策：不评分、不排名、不打卡；正向框架；信任余额自动静默
4. **隐私恐惧。** 对策：本地优先 + 可见的暂停 + 审计日志
5. **电量/性能/大模型成本。** 对策：会话级而非秒级判断，一天 100 次小模型调用完全可承受
6. **手机端做不出来导致叙事崩塌。** 对策：一开始就把它定义成"桌面为主 + 手机轻量"，别过度承诺

## 10. 需要验证的五个假设

| 假设 | 最快的验证方式 |
|---|---|
| 人愿意被记录到什么粒度？ | **绿野仙踪法**：找 10 个人，你人工看他们屏幕 3 天，每天手写一份日报发给他们。两周出结论，零代码 |
| "它记得我说过的话"是否构成留存？ | 同上，第 4 天开始引用他们前三天说过的话，看反应 |
| 每天能容忍几次打断？ | 分 1 / 3 / 6 次三组，跑两周看留存和卸载理由 |
| 用户想被纠正还是被鼓励？ | 同一份周报做两个语气版本，A/B |
| 谁最先愿意付钱？ | 见下节 |

## 11. 定位与人群楔子

**别做通用助手。** 先服务一个高痛人群，他们的容忍度最高、口碑传播最强。

三个候选：

- **ADHD 人群**（最优）——刚需极强，市面上工具都不合适，社区活跃且乐于分享。缺点是设计要格外小心，不能制造自责
- **考研 / 自学编程的人**——目标明确、周期长、进度焦虑强、愿意付费
- **自由职业者**——没有老板，最需要外部节律

命名方向：`伴` / `边上` / `守夜` / `Pace` / `Offscreen`（"屏幕之外"）

**一句话 pitch**：
> 大多数工具帮你管理时间。它只是坐在你旁边，知道你本来想做什么。

## 12. 我认为你现在就要决定的三个取舍

1. **"监督者"还是"同伴"？** 所有文案、图形、算法阈值都从这里分叉。选同伴。
2. **"全平台"还是"桌面为主 + 手机轻量"？** 选后者。
3. **"通用助手"还是"先打一个高痛人群"？** 选后者，ADHD 或考研。

这三个决定之后，上面所有细节才有唯一解。
